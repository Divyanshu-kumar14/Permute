## 3. Coverage mechanics

CMake names objects `msg.c.o`, so `gcov -o <dir> kernel/msg.c` looks for `msg.gcno` and fails. Passing the `.gcno` directly (`gcov --json-format path/to/msg.c.gcno`) works and gives structured counts.

The report unions covered line numbers across every object file that instrumented a source, because a file can appear in more than one target. Groups are assigned by path, with `kernel/trace.c` and `kernel/blake3.c` counted as **log** rather than kernel so the codec's coverage is visible as its own number.

`oracle` reports `n/a`, not 0%. A zero would be indistinguishable from dead code, and the oracles do not exist until P2.

## 4. Portability

**musl (x86_64).** Two glibc dependencies had to be isolated:

- `abi/alloc.c`'s interposition block calls `__libc_malloc` and friends. It is now compiled only under `__GLIBC__`; the allocator core still builds and is tested through the prefixed object. The probe that links the interposed build is a CMake option, off in the musl image.
- `pthread_equal` is a function-like macro in musl, which expanded inside the generated prototype in `permute_iface.h`. The header undefines it before expanding the definition file.

The scenario set is not built in the musl image: s07 uses `pthread_mutexattr_setprioceiling`, which musl does not implement. NFR-11 asks the portability jobs for the unit suite.

**aarch64.** The nightly workflow uses `docker/setup-qemu-action` and an arm64 Ubuntu container, then runs `make build && make unit`. It proves the code compiles and the suite passes on the architecture; it says nothing about performance, and the artifact is not a substitute for real hardware.
